## 1. 共同约定

### 0.1 单位与导出

| 项 | 约定 | 为什么 |
| --- | --- | --- |
| 单位 | 1 Unity unit = 1 米 | 尺寸不对是 3D 交接最常见的问题 |
| 轴向 | Y 轴向上，`+Z` 朝前 | 和 Unity 一致，免得进引擎要转 |
| 轴心 | 道具在底部中心；角色在脚底中心 | 否则摆放会悬空或陷地 |
| 变换 | 导出前 Apply All Transforms | 带缩放/旋转的 FBX 会在引擎里出怪比例 |
| 缩放 | 正数，不要用镜像缩放 | 负缩放会让法线翻转、面变黑 |
| 格式 | `.fbx` | 不交 `.blend` / `.max` |

### 0.2 贴图

| 项 | 约定 |
| --- | --- |
| 尺寸 | 1024 × 1024（主道具可 2048），必须是 2 的幂 |
| 通道 | `_Albedo`（sRGB）、`_Normal`（Normal Map，sRGB **关**）、`_MaskMap` |
| MaskMap | R = Metallic，G = AO，B = 0（不用），A = Smoothness |
| 命名 | `<资产名>_Albedo.png` 等，和 FBX 同名 |

### 0.3 通用验收

**技术**（工具自动判定，全绿才进入美术评审）：

- 文件齐全、命名合法、贴图尺寸是 2 的幂
- 面数不超预算、包围盒尺寸在容差 ±10% 内
- 轴心在底部中心、无负缩放、UV 不为空
- 法线贴图导入类型正确、Albedo 开 sRGB 而法线/Mask 不开
- 材质由工程统一生成（URP/Lit），不要自带一堆 `Material 1`

**美术**（助教人工判定）：剪影可读、比例可信、材质真实、风格统一。

## 2. 课题一 · 道具建模

**目标**：从零完成一套可进引擎的低模道具，并体验一次高模→低模烘焙。

| 道具 | 参考尺寸（米） | 面数上限 | 备注 |
| --- | --- | --- | --- |
| 长剑 | 长 1.1 | 3000 | 硬表面，练卡线 |
| 圆盾 | 直径 0.7 | 3000 | 曲面 + 纹样，练 UV 布局 |
| 药瓶 | 高 0.2 | 2000 | 玻璃/发光材质 |
| 火把 | 长 0.6 | 3000 | 木 + 金属 + 布，天然多材质 |
| **宝箱（主道具）** | 0.9 × 0.6 × 0.6 | 8000 | **必须做高模→低模烘焙** |

**交付清单**

```
DropHere/
├── sword.fbx / sword_Albedo.png / sword_Normal.png / sword_MaskMap.png
├── shield.fbx / ...
├── potion.fbx / ...
├── torch.fbx / ...
├── chest.fbx / ...            ← 主道具，2048 贴图
└── chest_high.fbx             ← 高模（只用于烘焙，不进引擎）
```

另外附一张**线框截图**（Blender/Maya 里开线框，能看出布线）。

**制作要求**

- 宝箱：先做高模（倒角、铆钉、木纹起伏），再拓扑低模，烘焙 Normal + AO（AO 进 MaskMap 的 G 通道）
- 其余四件：低模 + 手绘/材质流程即可，不强制烘焙
- 五件共用一套风格：同一光源方向、同一饱和度、同一描边/磨损逻辑

**常见错误**

- 轴心在几何中心 → 摆放悬空
- 撑大贴图分辨率来掩盖 UV 拉伸
- 宝箱高模直接减面，没有重新拓扑 → 法线烘焙全是脏边

## 3. 课题二 · 材质

**目标**：掌握 PBR 贴图绘制、通道打包、UV 展开与铺设。

**5 套，分两类**

| 类型 | 名称 | 说明 |
| --- | --- | --- |
| 可平铺 ×3 | 岩石 / 金属 / 木材 | 必须无缝，在 2×2 地砖上检查接缝 |
| 贴模型 ×2 | 木箱 / 石柱 | 工程提供 CC0 低模（自带原 UV），你需要**清空原 UV 重新展**再画 |

**交付清单**

```
DropHere/
├── rock_Albedo.png / rock_Normal.png / rock_MaskMap.png
├── metal_...
├── wood_...
├── crate.fbx + crate_*.png     ← 自己展 UV 的模型
├── pillar.fbx + pillar_*.png
└── 说明.md                      ← 写清每套材质的思路（可选）
```

**制作要求**

- 平铺材质：贴图必须能四边无缝；接缝检查在预览场景的 2×2 地砖上做
- 贴模型材质：纹素密度要均匀（1 米约 512–1024 像素），木箱的木板缝要对齐 UV 缝
- 金属度/粗糙度不要全填 0 或 1，要有变化（磨损、油污、边缘高光）
- AO 只烘在模型材质上；平铺材质的 MaskMap G 填 1

**常见错误**

- 法线贴图没关 sRGB → 材质整体发灰
- 平铺材质有明显接缝 → 四边像素不连续
- 纹素密度不均 → 同一个模型上有的地方糊、有的地方锐

## 4. 课题三 · 场景

**目标**：在给定的白模和套件上做美术打磨——构图、材质、打光，而不是从零找素材。

**题目**：**「废弃的炼金工坊一角」**

**工程提供**

| 文件 | 说明 |
| --- | --- |
| `Kit.fbx` | 一套低模套件（墙、地、柱、箱、桶、灯、杂物等），统一 1 m 网格，白模无材质 |
| `Blockout.fbx` | 立方体拼的 4×4 m 场景白模（12 个方块）：地面、三面墙（左墙带窗洞）、L 形隔断、炼金炉体、工作台、货架、平台 |

**规则**

- **只能用提供的 Kit**：可以缩放、旋转、复制、隐藏，但**不能引入任何外部模型**
- 方块可以被 Kit 替换或包住，但整体占地和通道关系不能改——所有人起点一致，比的是美化
- 材质自己做，**≤ 4 套**；贴图默认 1024，关键面可 2048
- 打光自由，最终交一张 1920×1080 渲染图

| 项 | 规格 |
| --- | --- |
| 尺寸 | 4 m × 4 m，包围盒不超过 4×4×4 |
| 面数 | ≤ 30,000 tris |
| 贴图 | ≤ 4 套，单张 ≤ 2048 |
| 模型来源 | 只能用 `Kit.fbx`，不允许外部模型 |
| 必须包含 | 至少 1 件 Kit 道具、1 处自发光处理 |

**交付清单**

```
DropHere/
├── Diorama.fbx     ← 贴图嵌入 FBX（DCC 导出时勾 Embed Textures）
└── final.png       ← 打好光的 1920×1080 渲染图
```

**验收要点**

- 技术：包围盒 ≤ 4×4×4、面数 ≤ 30k、贴图 ≤ 4 套、mesh 名能对上 Kit（防止夹带外部模型）
- 美术：构图有视觉中心、前中后景层次清楚、材质统一、打光能看出主光方向

**常见错误**

| 现象 | 原因 |
| --- | --- |
| 交上来还是白模 | 方块没替换，只挪了位置 |
| 同一场景里物件比例忽大忽小 | Kit 导入时没统一缩放 |
| 材质花、不像一个场景 | 材质套数超过 4 套，或贴图分辨率不统一 |
| 画面平 | 只有环境光，没有主光方向 |

## 5. 课题四 · 骨骼动画

**目标**：用统一骨架完成一套可用的角色动画，并理解游戏里的状态切换。

**工程提供**（放在 `Assets/Tasks/Task4_Character/Base/`）

- `Dummy.fbx`：白色低模假人，Humanoid 骨架（22 根人体骨骼 / 43 根骨架节点），CC0
- `BaseCharacter.prefab`：已挂 Animator 与材质，可直接拖进场景
- 角色约 2.4 单位高，脚底在原点下方约 0.2，预览按包围盒对齐地面
- 你**不需要**建模、绑定、刷权重，只负责动画

**三个动画**

| 动画 | 时长 | 循环 | 说明 |
| --- | --- | --- | --- |
| Idle | 1.0–1.2 s | 是 | 待机呼吸，重心有起伏，首尾无缝 |
| Run | 0.6–0.8 s | 是 | 跑步循环，至少一个完整步幅 |
| StartRun | 0.2–0.3 s | 否 | 从静止到跑起来的起步过渡 |

**制作要求**

- 24 fps 制作，原地动画（In Place），**不要 Root Motion**
- `StartRun` 的**最后一帧要和 Run 的第一帧对得上**，否则起步会跳
- 重心转移要有：起步时身体前倾、脚蹬地、手臂摆动跟上
- 只做起步、不做收步（Run→Idle 由引擎 0.1 s 交叉淡入完成）

**交付清单**

```
DropHere/
├── Idle.fbx
├── Run.fbx
├── StartRun.fbx         ← 推荐：每个动画一个文件，文件名就是动画名
└── preview.mp4          ← 可选，10 秒录屏
```

也支持一个 `Animation.fbx` 里带三个同名 take（进阶用法）。

**状态机**（助教维护，你不用管）

```
Idle --(Speed>0.1)--> StartRun --(exitTime 0.9)--> Run --(Speed<0.1)--> Idle
```

如果 `StartRun` 没交，生成器会跳过这个状态、直接 Idle→Run，不会把角色卡死。

**常见错误**

- 三个 take 名字不对（`Armature|Idle` 这种），导入后识别不到
- 跑步循环首尾接不上 → 每圈抖一下
- 起步动画第一帧和 Idle 的姿势差太远 → 切换时弹一下
