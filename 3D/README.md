## 0. 通用约定

| 项 | 约定 |
| --- | --- |
| 单位 | 1 Unity unit = 1 米，按真实尺度 |
| 轴向 | Y 轴向上，`+Z` 朝前 |
| 轴心 | 道具在底部中心，角色在脚底中心 |
| 导出 | FBX，应用全部变换（Apply All Transforms），不带缩放/旋转 |
| 贴图 | 默认 1024，主道具可 2048，必须是 2 的幂 |
| 法线 | Tangent Space，导入类型设为 Normal Map，sRGB 关闭 |
| 源文件 | `.blend` / `.max` 一律不提交 |

贴图命名统一三张：

| 后缀 | 内容 | 导入设置 |
| --- | --- | --- |
| `_Albedo` | 颜色 | sRGB 开 |
| `_Normal` | 法线 | Normal Map 类型，sRGB 关 |
| `_MaskMap` | R 金属度、G AO、A 光滑度 | sRGB 关 |

## 1. 课题一 · 道具建模

**目标**：从零完成 5 件可进引擎的低模道具，并体验一次高模→低模烘焙。

| 文件 | 道具 | 参考最大边 | 面数上限 |
| --- | --- | --- | --- |
| `sword.fbx` | 长剑 | 1.1 m | 3,000 |
| `shield.fbx` | 圆盾 | 0.7 m | 3,000 |
| `potion.fbx` | 药瓶 | 0.25 m | 2,000 |
| `torch.fbx` | 火把 | 0.6 m | 3,000 |
| `chest.fbx` | 宝箱 | 0.9 m | 8,000（要做高模烘焙） |

### 交付

```
DropHere/
├── sword.fbx   sword_Albedo.png   sword_Normal.png   sword_MaskMap.png
├── shield.fbx  ...
├── potion.fbx  ...
├── torch.fbx   ...
└── chest.fbx   ...            ← 宝箱贴图可用 2048
```

另外附一张**线框截图**，能看出布线。

### 制作要求

- 宝箱：先做高模（倒角、铆钉、木纹起伏），再拓扑低模，烘焙 Normal + AO（AO 进 MaskMap 的 G 通道）
- 其余四件：低模 + 手绘/材质流程即可，不强制烘焙
- 五件共用一套风格：同一光源方向、同一饱和度、同一磨损逻辑
- 每件必须有 UV，轴心在底部中心，不要负缩放

### 验收

- 面数不超上限（超 20% 直接判错）
- 最大边不超过参考尺寸的 1.3 倍
- 有 UV、轴心在底部、贴图三张齐全
- 美术：剪影可读、比例可信、五件风格统一

## 2. 课题二 · 材质

**目标**：掌握 PBR 贴图绘制、通道打包、UV 展开与铺设。

| 类型 | 文件 | 说明 |
| --- | --- | --- |
| 可平铺 ×3 | `rock` / `metal` / `wood` | 必须四边无缝，预览里按 2×2 平铺检查 |
| 贴模型 ×2 | `crate` / `pillar` | 工程提供模型（`Base/Crate.fbx`、`Base/Pillar.fbx`），你需要**清空原 UV 重新展** |

### 交付

只交贴图，不交模型：

```
DropHere/
├── rock_Albedo.png    rock_Normal.png    rock_MaskMap.png
├── metal_...
├── wood_...
├── crate_...
└── pillar_...
```

工程会按名字自动生成 URP/Lit 材质，并贴到球体和指定模型上。

### 制作要求

- 1024 × 1024，必须是 2 的幂
- 平铺材质四边必须无缝；接缝看预览里球体和 2×2 平铺的效果
- 贴模型材质纹素密度要均匀（1 米约 512–1024 像素），木箱的木板缝要对齐 UV 缝
- 金属度/粗糙度要有变化，不要全填 0 或 1
- AO 只烘在模型材质上；平铺材质的 MaskMap G 填 1

### 验收

- 五套的 Albedo 齐全；法线/Mask 缺失会警告
- 法线图导入类型是 Normal Map，法线和 Mask 的 sRGB 关闭
- 美术：平铺无缝、纹素密度均匀、五套材质风格协调

### 验收

- 技术：面数、材质数、包围盒不超限
- 美术：构图有视觉中心、前中后景层次清楚、材质统一、打光能看出主光方向

## 4. 课题四 · 骨骼动画

### 工程提供的基础角色

| 文件 | 说明 |
| --- | --- |
| `Base/Dummy.fbx` | 白色低模假人，Humanoid 骨架：22 根人体骨骼 / 43 根骨架节点 |
| `Base/BaseCharacter.prefab` | 已挂 Animator 与材质 |

- 素材是 **CC0**，可以放心使用与修改
- 你**不需要**建模、绑定、刷权重，只负责动画
- 角色约 2.4 单位高，脚底在原点下方约 0.2，预览会自动对齐地面
- **不要修改 `Base/` 目录**

### 交付

推荐**每个动画一个文件**：

```
DropHere/
├── Idle.fbx
├── Run.fbx
└── StartRun.fbx
```

文件名就是动画名，不用管 DCC 里 Action 叫什么。也可以交一个 `Animation.fbx` 带三个同名 take（进阶用法）。

| take | 时长 | 循环 | 要求 |
| --- | --- | --- | --- |
| `Idle` | 1.0–1.2 秒 | 是 | 待机呼吸，重心有起伏，首尾无缝 |
| `Run` | 0.6–0.8 秒 | 是 | 跑步循环，至少一个完整步幅，首尾无缝 |
| `StartRun` | 0.2–0.3 秒 | 否 | 从静止到跑起来的起步过渡 |

- **24 fps**，原地动画（In Place），**不要 Root Motion**
- `StartRun` 的最后一帧要和 `Run` 的第一帧对得上
- 只做起步、不做收步——收步由引擎 0.1 秒交叉淡入完成

### 状态机（助教维护）

```
Idle --(Speed>0.1)--> StartRun --(exitTime 0.9)--> Run --(Speed<0.1)--> Idle
```

没交 `StartRun` 时会直接 `Idle -> Run`，不会卡死。

### 验收

- 技术：三个 clip 名字正确、时长在区间内、Idle/Run 循环、StartRun 不循环
- 美术：重心转移可信、跑步循环首尾自然、起步有加速感

## 7. 常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 模型全黑 | 材质 Shader 不兼容，或法线图 sRGB 没关 | 用 URP/Lit；法线图设为 Normal Map |
| 模型是粉的 | 材质 Shader 不是 URP 版本 | 换 `Universal Render Pipeline/Lit` |
| 模型悬空 / 陷地 | 轴心不在底部 | 在 DCC 里把轴心移到脚底/底部中心再导出 |
| 比例不对 | 导出时没按米制 | 统一 1 unit = 1m，重新导出 |
| 面是黑的 | 负缩放导致法线翻转 | 应用变换，别用镜像缩放 |
| 识别不出动画 | 文件名和 take 名都不是 Idle/Run/StartRun | 按 `Idle.fbx` / `Run.fbx` / `StartRun.fbx` 命名 |
| 每跑一圈抖一下 | 首尾姿势不一致 | 让最后一帧和第一帧完全对齐 |
| 贴图发灰 | 法线图没关 sRGB | 导入时关掉 sRGB |
| 平铺有接缝 | 四边像素不连续 | 用平铺工具重新处理边缘 |
